# Ambient signed F–K full-pipeline null, version 2

## Question

The directional F–K wedge retains energy with apparent velocity between 2.5
and 4.5 km/s. A ridge visible after that projection cannot, by itself, prove
that the original data contained an ordered wave with that velocity. This null
therefore destroys physical coherence **before** F–K filtering and repeats the
same downstream workflow.

## Frozen observed workflow

- Input: one-minute Nano DAS records selected by date and file index.
- Preprocessing: 5–20 Hz Butterworth bandpass and 5 s running-absolute-mean
  temporal normalization.
- Geometry: channel 0 is the top virtual source; receivers are approximately
  50–700 m from channel 0 along the fiber.
- Signed projections: `F*K < 0` is scored at positive lag and `F*K > 0` is
  scored at negative lag, following the corrected synthetic sign test.
- Velocity score: median normalized correlation sampled along the moveout
  time `lag = signed receiver offset / trial velocity`.
- Selection statistic: the maximum absolute velocity score from 2.5 to
  4.5 km/s. A familywise statistic takes the maximum over both signed branches.

The 2.5–4.5 km/s region must remain frozen. Changing it after inspecting the
same observed/null comparison invalidates the reported empirical p value.

## Null families

### Channel permutation

Channel 0 remains fixed, while all other traces are randomly reassigned to
fiber coordinates before F–K filtering. The transform preserves the trace
inventory, spectra, amplitudes, sample distributions, record duration, and
virtual-source trace. It destroys ordered spatial moveout. Because all
production preprocessing is channel-wise, permuting after preprocessing is
equivalent to permuting the raw channel order first and then preprocessing.

### Independent circular time shifts

Channel 0 remains fixed, while every other trace receives an independently
drawn circular time shift before F–K filtering. Each trace and its Fourier
amplitude spectrum are preserved exactly, but phase relationships with the
source and neighboring channels are destroyed. This surrogate has one
artificial wrap boundary per shifted trace, so it is interpreted separately
from the channel-permutation null.

Each realization is seeded reproducibly from the global seed, null method,
null index, and input path. The observed data and every surrogate then pass
through the same F–K filtering, correlation, stacking, and velocity scoring.

## Supported claim

If the observed familywise score exceeds the surrogate distribution, the
result supports the restricted statement that the ridge requires pre-F–K
spatial or phase coherence and is not generated by the fixed wedge acting on
these coherence-destroyed surrogates. The test directly addresses a
filter-induced-selection concern that a receiver-distance permutation applied
only after F–K filtering cannot address.

## What the test cannot establish

- It cannot establish that ambient correlations have converged to a Green’s
  function.
- It cannot identify the wave type or convert apparent velocity to formation
  Vp.
- It cannot prove the source distribution is isotropic or stationary.
- Its inference remains conditional on the frozen preprocessing and F–K wedge.
- Artificial surrogates do not reproduce every possible form of spatially
  correlated ambient noise.
- An empirical p value cannot be smaller than `1 / (number of nulls + 1)`.

## Commands

Deterministic helper tests:

```bash
conda activate das
python awd_clean/test_ambient_fk_full_pipeline_null_v2.py
```

One-file smoke test with three realizations from each null family:

```bash
conda activate das
python awd_clean/ambient_fk_full_pipeline_null_v2.py \
  --date 2024-12-20 --start 0 --nfiles 1 --nulls 3 \
  --output-dir awd_clean/ambient_transfer/fk_full_pipeline_null_v2_smoke
```

The JSON contains assumptions, statistics, empirical p values, and explicit
limitations. The NPZ contains observed stacks and velocity-score curves, every
null score curve, the first surrogate stack for visual QC, and familywise null
statistics. Small smoke-run p values are only code validation, not scientific
inference.
